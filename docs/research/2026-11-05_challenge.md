# Bharat AI-SoC Challenge 2026-27: Phase 1 rules for PS5 (Manufacturing & Industry 4.0)

SUMMARY: The only official rules source is the Arm-Developer-Labs challenge page. armbharatchallenge.com just redirects to it. The page was last changed on 3 Nov 2026, and announcements are posted there. The Phase 1 deadline is 23 November 2026. It was moved forward from 30 November on 16 Oct 2026 (PR #188), which also moved Phase 2 to 5 Feb 2027 and the finals to 15-16 Feb 2027. No time zone is given anywhere. For Phase 1, teams submit a report, source code and a demo. PS5 lists four deliverables: source code, an application, a demonstration video and a technical report. The project must be on GitHub and sent through a "challenge submission form". The form's URL is not public. In edition 1 the form was sent directly to participants. No report template, page or word limit, required sections, video length or mandatory metrics are published, and there are no official judging weights. The best published guide is the PS5 mentoring video (Arm Education, 2 Nov 2026). It says judges look at five things: detection quality, real-time performance on the device, how useful the advice is, the operator experience, and documentation. The same video gives a reference architecture: camera, then a vision model, then a structured defect record (type, severity, location, confidence), then Llama advice, then an alert and a log entry. It also says the report must describe the Hailo/HailoRT vision pipeline and the ExecuTorch Llama pipeline clearly and separately. The rules require a Llama-family model for the advisory part, run on the device with ExecuTorch. The page's example is Llama 3.2 1B/3B-Instruct or a fine-tuned or distilled version, so fine-tuning is allowed. No ExecuTorch version is mandated. If the Hailo accelerator is used, Llama must run on the Pi's Arm CPU through ExecuTorch, so running Llama on the Hailo-10H with hailo-ollama would not meet the rule. Teams have 1-3 Indian nationals from one college with a faculty mentor, and registration closed on 19 Oct 2026. Entries must be original and the team's own work. No open-source licence is required, but the team is responsible for the IP rights to all code, data and models it uses. The page links one course, "Optimize and deploy AI inference with ExecuTorch on Arm". Its Modules 1-2 run on a Pi 5 with Raspberry Pi OS Trixie and support an Apple-silicon Mac as the development machine. The Arm Learning Path for Llama on a Pi 5 and the ExecuTorch Raspberry Pi tutorial are the main Llama references.

The team could miss the form or break an unpublished limit, such as video length or page count. => Email support@ today. Watch the Team Leader's inbox and spam folder. Keep the report short (about 10-15 pages, an assumption) and the video under 5 minutes (also an assumption). Submit by 22 Nov IST.

- Compiling a custom Hailo-10H model needs DFC v5.x on Linux x86_64, and the team has only a Mac. => Use Ultralytics Platform's managed Hailo export or a rented x86 Ubuntu GPU machine. Keep a fallback that runs vision on the CPU with ExecuTorch INT8, or use Hailo Model Zoo HEFs to show the pipeline.
- Running Llama on the Hailo-10H (hailo-ollama) or with llama.cpp would break the mandatory Llama-via-ExecuTorch-on-Arm-CPU rule. => Run Llama only through an ExecuTorch .pte with llama_main or the ExecuTorch runner on the Cortex-A76, and state this explicitly in the report.
- A .pte exported with one ExecuTorch version can fail to load on a runtime built from another version. Cross-compiled binaries can also fail with a GLIBC mismatch (2.38 needed vs 2.36 on the Pi). => Pin one version (1.5.1 / release/1.5) everywhere, re-export the .pte yourself, build natively on the Pi under Trixie, and record the versions in the README.
- Licence or IP non-compliance could breach the challenge's IP clause: Llama 3.2 licence terms, AGPL-3.0 from Ultralytics, and non-commercial datasets (MVTec AD, KolektorSDD). => Add the NOTICE file and 'Built with Llama', pick a repo licence compatible with AGPL if Ultralytics is used, cite the datasets, and do not redistribute weights or images in the repo.
- Using the AI Camera's IMX500 on-sensor NPU for detection may not count as an accepted vision pipeline because it is not listed in the hardware or pipeline rules. => Use the IMX500 only as a camera sensor for Phase 1 unless tech-queries@ confirms it is allowed, and keep vision on the Hailo-10H or the CPU.
- The Arm Learning Path uses Llama 3.1 8B. Its export runs out of memory at 32 GB RAM or less, and decoding on the Pi would be too slow for real-time advice. => Use Llama 3.2 1B-Instruct (or 3B) in INT4, which is the size the challenge page gives as its example.
- The rubric is unknown, so effort could go into areas judges do not weight. => Cover all five aspects from the PS5 video and the seven edition-1 criteria, and give each its own measured result in the report.
