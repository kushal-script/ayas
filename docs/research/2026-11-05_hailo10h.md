# Raspberry Pi AI HAT+ 2 (Hailo-10H) vision toolchain as of Nov 2026: install, demos, precompiled HEFs, custom-model compilation, tiling/anomaly options, and the fastest path to a custom defect detector by 18 Nov 2026

SUMMARY: The "40 TOPS AI HAT" is almost certainly a Hailo-10H board. On the official Raspberry Pi AI HAT+ 2, the 40 TOPS figure is INT4 (20 TOPS at INT8), the board has 8 GB of its own LPDDR4X, and it uses the Pi 5's only PCIe FPC port, so an NVMe drive cannot be added in the normal way. Raspberry Pi says its vision performance is comparable to the 26 TOPS Hailo-8 AI HAT+. Third-party Hailo-10H HATs also exist, so run `hailortcli fw-control identify` and look for `HAILO10H` to confirm.

On Pi OS Trixie 64-bit, install with `sudo apt install dkms hailo-h10-all`. I read the official apt index (dated 4 Nov 2026) and it still ships HailoRT 5.1.1 (h10-hailort, h10-hailort-pcie-driver and python3-h10-hailort, Python 3.13 only), plus hailo-tappas-core 5.1.0 and rpicam-apps 1.14.0. Hailo's GitHub has moved on to HailoRT and DFC 5.5.0 (Model Zoo v5.5.0, released 31 Oct). This version gap is the main hazard. HEFs must be built with the same 5.1.x line: community reports say a 5.2.0 HEF fails on 5.1.1 with HAILO_NOT_IMPLEMENTED, and Hailo staff say the Pi officially supports only 5.1.1. So compile with DFC 5.1.0 and Model Zoo tag v5.1.0. Ready-made v5.1.0 Hailo-10H HEFs (yolov8n/s/m, yolov11n/s/m, yolov8n_seg, unet_mobilenet_v2, resnet, efficientnet_lite0, CLIP image encoders) download from S3. YOLO26 is not available for this runtime.

Out-of-the-box demos with an H10 HEF are rpicam-apps' `hailo_yolov8_inference.json` (yolov8m_h10), the pose, yolov5n-seg and classifier JSONs, and `examples/hailo/detect.py` in the picamera2-examples repo. The YOLOv6 and YOLOX JSONs have no H10 model. Docs don't say whether the IMX500 AI Camera can feed the Hailo pipeline, but it should work as a normal libcamera camera; test this on day 1.

The DFC (compiler) runs only on x86_64 Ubuntu 22.04/24.04 (or WSL2) with Python 3.10–3.12. A GPU is optional but needed for full-quality optimisation: Pascal/Turing/Ampere, driver 525, CUDA 12.5.1. It needs a free Developer Zone login. It is not supported on macOS or Apple Silicon. One user got it working in Docker with Rosetta, but QEMU segfaults. Hailo's own hailo-apps notebook targets `--hw-arch hailo10h` in Google Colab with a T4 GPU, so Colab or a cloud x86 VM is the realistic compile host for a Mac team.

Small defects disappear when a 12 MP frame is shrunk to 640 px. At about 20 cm the AI Camera covers about 64 µm/px at full resolution versus about 0.41 mm/px when the frame is downscaled to 640 (calc). So tile the plate region at native scale and train on tiles of the same scale. hailo-apps already ships a `hailo-tiling` app.

Hailo has no anomaly-detection models in its Model Zoo. Community attempts with EfficientAD, FastFlow and PaDiM hit compile problems. The practical options are a pure-conv backbone or CLIP image encoder on the Hailo, with kNN scoring on the CPU.

Under the brief, Llama must run on the Arm CPU through ExecuTorch. The Hailo is for vision only: do not use hailo-ollama, the Hailo GenAI model zoo or VLMs there for the required advisory part. Also avoid installing hailo-gen-ai-model-zoo, because it can pull in the Hailo-8 `hailort` package and remove the H10 stack.

Fastest path: get the Pi stack and demos working today. Prove the compile chain on Colab with a stock COCO YOLOv8n ONNX by about 7 Nov, and check that HEF runs on the Pi. Then train YOLOv8n on tiled images of your own aluminium defects, compile with DFC 5.1.0 using 1024 raw calibration tiles, and run it through Picamera2's Hailo class with tiling by about 18 Nov. Fallback: run the same model on the Pi CPU with NCNN, which the brief allows, and/or use precompiled Hailo HEFs (CLIP encoder) for anomaly scoring with no compile step.

## Recommendations
- Day 0 (5-6 Nov): identify the HAT. Flash Raspberry Pi OS Trixie 64-bit, then run `sudo apt update && sudo apt full-upgrade -y && sudo rpi-eeprom-update -a && sudo reboot`, then `sudo apt install dkms hailo-h10-all && sudo reboot`. Run `hailortcli fw-control identify` and expect 'Device Architecture: HAILO10H' and firmware 5.1.1. Also check `lspci | grep -i hailo`, `dmesg | grep -i hailo` and `ls /lib/firmware/hailo/hailo10h/`. `apt-cache policy hailort` must show it as not installed.
- Freeze the working stack: `sudo apt-mark hold h10-hailort h10-hailort-pcie-driver python3-h10-hailort hailo-h10-all hailo-tappas-core python3-hailo-tappas rpicam-apps-hailo-postprocess`. Never install hailo-all, hailort, hailort-pcie-driver or hailo-gen-ai-model-zoo.
